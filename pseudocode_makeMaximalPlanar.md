## Overview

This document describes the pseudocode for the C++ wrapper class `Pgr_makeMaximalPlanar`
that will call `boost::make_maximal_planar` and return the set of edges needed to triangulate
a biconnected planar graph to maximal planar density (E = 3V − 6).

**Return type:** `II_t_rt` (two BIGINT fields: `start_vid`, `end_vid`)
The `seq` column is generated by the C SRF wrapper as `call_cntr + 1`.

**Files modeled after:**
- `include/planar/makeBiconnectedPlanar.hpp` (Phase 1 — same module, built first)
- `include/components/makeConnected.hpp` — for the mutable graph pattern
- `src/planar/boyerMyrvold_driver.cpp` — for driver structure
- `src/components/makeConnected_driver.cpp` — for `II_t_rt` return pattern

## ⚠️ PROPOSAL DEVIATION (Critical)

**Proposal Section 10.4** describes using `pgr_collect_edges_visitor` (non-mutating) for
`makeMaximalPlanar`. This is **INCORRECT**.

**Correct behavior:** The visitor MUST call `add_edge(u, v, g)` inside `visit_vertex_pair`
to keep the graph state consistent during face traversal.

**Why:** `triangulation_visitor::end_face()` (inside `make_maximal_planar`) calls
`adjacent_vertices(v₀, g)` mid-run to check which face vertices are already neighbors of the
min-degree vertex (Phase 5-6 of end_face). If newly added edges aren't reflected in the graph,
**Case B detection fails** — the algorithm won't find marked neighbors and will fall back to
Case A (fan triangulation) every time, potentially adding redundant or incorrect edges.

**Codebase confirmation:** `makeConnected.hpp` (lines 76-85) already uses the mutable graph
pattern — `boost::make_connected(graph.graph)` modifies the graph in-place, and new edges
are detected by comparing edge count before/after. Our visitor follows this same pattern of
graph mutation within the algorithm.

## Wrapper Class: `Pgr_makeMaximalPlanar<G>`

```
FILE: include/planar/makeMaximalPlanar.hpp

CLASS Pgr_makeMaximalPlanar<G> : public Pgr_messages

  TYPES (inherited from graph G):
    V   = vertex_descriptor
    E   = edge_descriptor
    E_i = edge_iterator

  PUBLIC:
    FUNCTION makeMaximalPlanar(graph) -> vector<II_t_rt>:
        RETURN generateMakeMaximalPlanar(graph)

  PRIVATE:
    FUNCTION generateMakeMaximalPlanar(graph) -> vector<II_t_rt>:

        // ──────────────────────────────────────────────
        // Step 1: Precondition checks
        // ──────────────────────────────────────────────
        IF num_vertices(graph.graph) < 3:
            throw std::string("Graph must have at least 3 vertices.")

        // ──────────────────────────────────────────────
        // Step 2: Compute planar embedding via Boyer-Myrvold
        // ──────────────────────────────────────────────
        // Same pattern as Phase 1 (makeBiconnectedPlanar).
        // Embedding is always recomputed internally — no optional parameter.
        // This is consistent with all existing pgRouting functions
        // (none accept an embedding parameter).

        embedding = vector<vector<edge_descriptor>>(num_vertices(graph.graph))

        CHECK_FOR_INTERRUPTS()

        is_planar = boyer_myrvold_planarity_test(
            boyer_myrvold_params::graph = graph.graph,
            boyer_myrvold_params::embedding = &embedding[0]
        )

        IF NOT is_planar:
            throw std::string("Graph is not planar.")

        // ──────────────────────────────────────────────
        // Step 3: Build EdgeIndexMap (same as Phase 1)
        // ──────────────────────────────────────────────
        // pgRouting's UndirectedGraph has no interior edge_index_t property.
        // Must construct explicitly using std::map + associative_property_map.

        edge_index_map = std::map<edge_descriptor, int>
        edge_count = 0
        FOR (ei, ei_end) = edges(graph.graph); ei != ei_end; ++ei:
            edge_index_map[*ei] = edge_count++

        edge_index_pmap = boost::associative_property_map<EdgeIndexMap>(edge_index_map)

        // ──────────────────────────────────────────────
        // Step 4: Get VertexIndexMap
        // ──────────────────────────────────────────────
        // ADDITIONAL REQUIREMENT vs Phase 1:
        // make_maximal_planar requires VertexIndexMap for neighbor marking
        // in triangulation_visitor::end_face() (Phase 5: timestamp-based marking).
        //
        // pgRouting's UndirectedGraph uses vecS for vertices, so
        // vertex_index is automatically provided by Boost.

        vertex_index_pmap = boost::get(boost::vertex_index, graph.graph)
        // This is "free" — vecS provides it automatically.

        // ──────────────────────────────────────────────
        // Step 5: Custom visitor (MUTATING — critical difference from Phase 1)
        // ──────────────────────────────────────────────
        // The visitor MUST call add_edge() to keep the graph accurate.
        // triangulation_visitor::end_face() reads adjacency mid-run
        // (adjacent_vertices call in Phase 5-6).
        //
        // Vertex IDs are extracted via graph[descriptor].id — same as Phase 1.

        STRUCT pgr_maximal_planar_visitor:
            result: vector<pair<int64_t, int64_t>>&
            graph_ref: G&    // reference to pgRouting graph wrapper

            FUNCTION visit_vertex_pair(u, v, g):
                // 1. Mutate graph: add edge so adjacency stays consistent
                boost::add_edge(u, v, g)

                // 2. Record the edge using pgRouting IDs
                //    graph_ref[u].id gives the original pgRouting vertex ID
                result.push_back({graph_ref[u].id, graph_ref[v].id})

        collected_edges = vector<pair<int64_t, int64_t>>
        visitor = pgr_maximal_planar_visitor{collected_edges, graph}

        // ──────────────────────────────────────────────
        // Step 6: Call Boost algorithm
        // ──────────────────────────────────────────────
        // Using Overload 1 (5 parameters):
        //   make_maximal_planar(g, embedding, vm, em, vis)
        //
        // 5 parameters because we need both VertexIndexMap AND EdgeIndexMap.
        // Cannot use simpler overloads because pgRouting's graph lacks
        // interior edge_index_t property.

        TRY:
            boost::make_maximal_planar(
                graph.graph,
                &embedding[0],
                vertex_index_pmap,
                edge_index_pmap,
                visitor
            )
        CATCH boost::exception -> rethrow
        CATCH std::exception  -> rethrow
        CATCH ...              -> rethrow

        // ──────────────────────────────────────────────
        // Step 7: Build result vector
        // ──────────────────────────────────────────────
        // IDs already extracted in the visitor (Step 5), so no mapping needed here.

        results = vector<II_t_rt>(collected_edges.size())
        FOR i = 0; i < collected_edges.size(); i++:
            results[i] = {collected_edges[i].first, collected_edges[i].second}

        log << "Edges to add for maximal planarity: " << results.size()
        log << "Expected total edges after: 3V-6 = " << (3 * num_vertices(graph.graph) - 6)

        RETURN results
```

## Driver: `makeMaximalPlanar_driver.cpp`

```
FILE: src/planar/makeMaximalPlanar_driver.cpp

FUNCTION pgr_do_makeMaximalPlanar(
    edges_sql,
    return_tuples,      // OUT: II_t_rt**
    return_count,       // OUT: size_t*
    log_msg,
    notice_msg,
    err_msg
):

    TRY:
        // Get edges from SQL
        hint = edges_sql
        edges = get_edges(edges_sql, true, false)

        IF edges.empty():
            *notice_msg = "No edges found"
            RETURN

        hint = nullptr

        // Build undirected graph
        undigraph = pgrouting::UndirectedGraph()
        undigraph.insert_edges(edges)

        // Call wrapper
        fn = Pgr_makeMaximalPlanar<UndirectedGraph>()
        results = fn.makeMaximalPlanar(undigraph)

        // Return results
        IF results.empty():
            // Already maximal planar — return 0 rows
            // (natural output: all faces are triangles, end_face() skips all)
            *return_tuples = NULL
            *return_count = 0
            RETURN

        *return_tuples = pgr_alloc(results.size(), *return_tuples)
        FOR i = 0 to results.size():
            *(*return_tuples + i) = results[i]
        *return_count = results.size()

    // Error handling: standard pgRouting pattern (throw std::string)
    CATCH AssertFailedException:
        *err_msg = except.what()
    CATCH const std::string&:
        *err_msg = to_pg_msg(ex)
        *log_msg = hint ? to_pg_msg(hint) : to_pg_msg(log)
    CATCH std::exception:
        *err_msg = except.what()
    CATCH ...:
        *err_msg = "Caught unknown exception!"
```

## Error Reporting

All errors use `throw std::string(...)` — matching the standard pattern used across the
entire pgRouting codebase (confirmed in `boyerMyrvold_driver.cpp`, `topologicalSort.cpp`,
`makeConnected_driver.cpp`, etc.).

| Condition | Error Message |
|-----------|---------------|
| V < 3 | `"Graph must have at least 3 vertices."` |
| Not planar | `"Graph is not planar."` |
| Not biconnected | `"Graph is not biconnected. Use pgr_makeBiconnectedPlanar first."` |
| No edges | Notice: `"No edges found"` |
| Already maximal planar | Returns 0 rows (natural: `end_face()` skips all triangles) |

## Key Design Decisions

1. **MUTATING visitor (critical):** Unlike Phase 1, the visitor calls `add_edge(u, v, g)`.
   This keeps the graph state accurate for `adjacent_vertices()` calls in
   `triangulation_visitor::end_face()` Phase 5-6. Without this, Case B optimization
   would never trigger, producing incorrect triangulations.

2. **VertexIndexMap (ADDITIONAL requirement vs Phase 1):**
   `make_maximal_planar` requires `AdjacencyGraph` concept AND `VertexIndexMap`.
   The `vertex_index` is free from `vecS` — just call `get(vertex_index, g)`.
   This was not needed for `make_biconnected_planar`.

3. **EdgeIndexMap constructed locally:** Same pattern as Phase 1.
   `std::map<E, int>` + `associative_property_map`. Required because pgRouting's graph
   lacks interior `edge_index_t`.

4. **ID extraction in visitor:** pgRouting IDs extracted via `graph[u].id` directly inside
   the visitor, rather than collecting descriptors and mapping later. This avoids the issue
   of descriptors potentially being invalidated by `add_edge()` calls.

5. **Embedding always recomputed:** No optional embedding parameter. Consistent with all
   existing pgRouting functions. After inserting biconnected edges, the old embedding is
   invalid anyway — must recompute via Boyer-Myrvold (O(V+E)).

6. **Biconnectivity check:** The wrapper will check biconnectivity using
   `biconnected_components()` before calling `make_maximal_planar`. If the graph has
   more than 1 biconnected component, throw the appropriate error. Implementation detail:
   `biconnected_components()` returns the number of components — if > 1, not biconnected.

## Differences from Phase 1 (makeBiconnectedPlanar)

| Aspect | Phase 1 (Biconnected) | Phase 2 (Maximal Planar) |
|--------|----------------------|-------------------------|
| Boost function | `make_biconnected_planar` | `make_maximal_planar` |
| Parameters | 4 (g, emb, em, vis) | 5 (g, emb, vm, em, vis) |
| Visitor mutates graph? | **No** | **Yes** (must call `add_edge`) |
| Needs VertexIndexMap? | No | Yes (for neighbor marking) |
| Needs AdjacencyGraph? | No | Yes (`adjacent_vertices`) |
| Preconditions | Connected + Planar | Biconnected + Planar + V≥3 |
| Max edges added | ≤ V−2 | 3V−6−E₀ |
| Postcondition | No articulation points | Every face is a triangle |
